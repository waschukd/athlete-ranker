# Working with this repo

## Response style
- **Commands only.** When the user needs to do something, reply with copy-paste
  command blocks and nothing else. No preamble, no explanation, no recap unless
  explicitly asked.
- Keep prose to an absolute minimum. One short line max if context is essential.
- Don't restate what a command does. Don't summarize after.
- **No markdown headings** (`#`, `##`, `###`). The terminal renders them at a
  larger size, so a reply that uses them looks like the font keeps changing.
- No tables, no bold-heavy summaries, no horizontal rules. Plain sentences and
  command blocks only. A short `-` list is fine when there genuinely are several
  items.

## Working rules (standing, from Dan)

- **Confirm before anything leaves the building.** Before sending any email, SMS, or survey invite, or pushing code to main, state the exact recipients (names and addresses), the subject or files, and the wording, then wait for an explicit "yes" in the same conversation. A past approval for one send does not cover another.
- **Named people are explicit instructions.** If Dan names a person for a list, include them even if a general rule would exclude them, and say so. Apply any general rule only to people he did not name, and say which ones it excluded.
- **Check live data before stating it.** Counts, statuses, access, and "is X done" answers come from a query run in this conversation, not from memory or an earlier summary. Say when a number was checked.
- **Restate multi-part requests first.** For a request with more than two parts or any irreversible action, restate each part as a numbered list before acting, and wait if anything is ambiguous.
- **Timing and tense matter in wording.** For evaluations, debriefs, and reports, write about what has happened (past tense), not "the season is underway" or "next season" unless Dan says so.
- **Don't claim done until verified.** Say "done" only after the result has been checked: the page loads, the email shows "ok", the record reads back correctly.
- **Report failures plainly.** If something didn't work or was done wrong, say it in the first sentence and say what was undone.
